# Проверка независимого заряда — 1.5-dev

Это экспериментальный режим `enco`. Он обращается к Bluetooth-сервису наушников без HeyMelody. Его работа на Enco Air2i ещё не подтверждена. Существующий режим `heymelody` сохранён.

1. Вручную установите `artifacts/AnyBuds-OriginOS-1.5-dev-debug.apk` поверх прежней версии.
2. Оставьте модулю области LSPosed для `com.android.bluetooth` и `com.android.vivo.tws.vivotws`. Область HeyMelody для нового режима не нужна.
3. В своём root-терминале задайте:

   ```sh
   settings put global twspopup_auto Enco
   settings put global twspopup_battery_source enco
   ```

4. Перезагрузите телефон после обновления модуля. В настройках приложений вручную остановите HeyMelody, чтобы проверять самостоятельное соединение и исключить конкуренцию за сервис наушников. Удалять приложение не требуется.
5. Переподключите уже сопряжённые наушники обычным способом. Наблюдайте popup. Клиент работает максимум 20 секунд после подключения; если данных нет, остаются `--`.
6. Сохраните лог из своего терминала:

   ```sh
   logcat -d -s TwsPopup
   ```

Ожидаемая цепочка: `Enco direct connecting` → `connected` → пакет `0x8200` → `battery notification subscription sent` → подтверждение `0x8201` и/или уведомление `0x204` → `source=enco_rfcomm L=... R=... case=...` → `Vendor report received source=enco` → `shown`/`updated`. Порядок подтверждения и уведомления может отличаться. Сообщение `20-second acquisition window ended` означает закрытие созданного клиентом сокета, а не отключение аудио.

Если остались `--`, нужен весь этот участок лога, включая исключение, а не только итоговые значения. Он различит отсутствие сервиса, отказ доступа, неподдерживаемую команду и отсутствие уведомления после подписки. Не запускайте HeyMelody во время основной проверки.

## Сценарии для пользователя

| ID | Проверка | Что записать |
| --- | --- | --- |
| E01 | HeyMelody остановлен, оба наушника подключены | L/R/кейс, время появления и диагностическая цепочка |
| E02 | По очереди подключён только один наушник | Какие части доступны; отсутствие не должно выдумываться из процента |
| E03 | Изменение состояния зарядки/кейса в первые 20 секунд | Какие уведомления пришли; закрытый кейс может не сообщать свой заряд |
| E04 | Отключение сразу после подключения, затем повторное подключение | Старые отчёты/окна не возвращаются; новая попытка работает отдельно |
| E05 | Воспроизведение музыки и обычный звонок | Нет обрывов/переключения аудио при подключении и закрытии служебного сокета |
| E06 | Закрыть popup рукой, дождаться нового отчёта | Popup не открывается повторно |
| E07 | После завершения попытки открыть HeyMelody для сравнения | Значения и время обоих измерений; HeyMelody может округлять вверх до десятков |
| E08 | Вернуться к `heymelody`, затем к `enco` с переподключением | Старый источник не подставляет свой кэш за новый |

Все E01–E08 пока ожидают ручной проверки. Никаких подключений к телефону или автоматических тестов устройства разработчиком не выполнялось.

Для возврата к проверенному вами пути:

```sh
settings put global twspopup_battery_source heymelody
```

Затем откройте HeyMelody с включённой областью LSPosed и переподключите наушники. Чтобы вернуться к исходному общему Android-заряду, удалите настройку через `settings delete global twspopup_battery_source` и переподключите. Новый клиент не меняет настройки наушников и не требует их сброса.
